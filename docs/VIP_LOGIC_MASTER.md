# VIP Club — нэгдсэн логик ба дутуу ажлын санамж

Шалгасан огноо: 2026-09-11. Энэ баримт нь одоогийн шийдвэр, хэрэгжилтийн нотолгоо, үлдсэн ажлыг нэг газраас унших зориулалттай. Бүх production урсгалыг өнөөдөр дахин шалгасан тайлан биш. UI шинэчлэлийн даалгаврыг тусад нь хариуцна.

## 1. Ямар төлөв юуг хэлэх вэ?

- **Батлагдсан шаардлага:** хийхээр зөвшөөрсөн бизнес дүрэм; код ажиллаж байгааг батлахгүй.
- **Локал шалгасан:** тодорхой candidate/test дээр passed; production биш.
- **Production түүхэн нотолгоотой:** нэрлэсэн өдөр deployment/runtime шалгалттай; өнөөдрийн бүх урсгалын баталгаа биш.
- **Шалгах үлдсэн:** нотолгоо хүрэлцээгүй; код огт байхгүй гэсэн үг биш.
- **Шийдвэр хэрэгтэй:** автоматаар дүрэм зохиож хэрэгжүүлэхгүй.
- **Хойшлуулсан:** одоогийн өдөр тутмын үйл ажиллагааны priority биш.

Linear-ийн 93 ажлаас 35 Done буюу 37.6% нь жинлээгүй таскийн төлөв. Prototype, documentation болон production ажлууд холилдсон учраас бүтээгдэхүүний бэлэн байдлын хувь гэж ашиглахгүй.

## 2. Одоогийн батлагдсан үндсэн логик

### Ажил горилогч → ажилтан → аппын эрх

1. Ажил горилогч анкет бөглөнө: өөрөө эсвэл өөрт нь очсон тусгай урилгын холбоосоор.
2. Анкет дээр Finex бүртгэл, аппын нууц үг, ажилтны төрөл шаардахгүй.
3. Менежер өөрийн салбарт ажилд авахыг батална; HR-ийн давхар эцсийн зөвшөөрлийг заавал хүлээхгүй.
4. Ажилд авах шийдвэрийн дараа менежер/HR албан тушаал, эхлэх өдөр, ажилтны төрлийг тохируулна.
5. Ажилтны төрөл: **Үндсэн / Хамтран ажиллах / Цагийн**. Төрөл ба төлбөрийн арга хоёр тусдаа ойлголт; энэ шатанд мөнгөн тариф заавал тохируулахгүй.
6. Бүжигчний тайзны нэр нэг салбарт давтагдахгүй. Тайзны нэр батлах нь Finex-ийн бодит ID холбоос батлагдсан гэсэн үг биш.
7. Аппын эрх идэвхжүүлэх нэг удаагийн холбоосыг ажилтны имэйлд илгээнэ. Нууц үгийг имэйлээр илгээхгүй.
8. Employee, User, application role, entertainer profile, branch assignment, Finex identity-г тусдаа төлөвөөр удирдана; нэг нь байгаагаар бусад нь бэлэн болохгүй.

Менежер/HR мэдээлэл засах эрхтэй; регистр өөрчлөхгүй. Нэг хүнийг дахин ажилд авахдаа шинэ identity үүсгэж давхардуулахгүй.

### Салбар солих ба ажлаас гарах

- Илгээгч салбарын менежер шилжүүлэх хүсэлт гаргана; очих салбарын менежер зөвшөөрөх/татгалзах эрхтэй.
- Хүлээгдэж буй хүсэлтийг илгээгч цуцалж болно; нэг ажилтанд нэг идэвхтэй хүсэлт.
- Сонгосон operational-day заагт шилжилт хэрэгжинэ. Хуучин салбарын ирц/борлуулалтын түүхийг шинэ салбарт шилжүүлж бичихгүй.
- Чөлөөлөлт нь ажилтан, профайл, аппын эрх, нээлттэй session, ирээдүйн хуваарьтай уялдана. Түүхийг устгахгүй.
- Салбар шилжүүлэх backend-д 2026-09-07 production readback/rollback бүхий synthetic test нотолгоо бий; үүнийг хийгдээгүй гэж дахин жагсаахгүй.
- Менежерийн чөлөөлөх болон rehire-ийн бүх одоогийн урсгалын баталгаа тусад нь шаардлагатай.

### Борлуулалт, ирц, AI

- Finex-ийн борлуулалт, ажилтны орлого, цалин, зэрэглэлийн оноо тусдаа хэмжигдэхүүн.
- Мэдээлэл байхгүй, холболт хүлээгдэж байгаа, жинхэнэ API алдаа, батлагдсан тэгийг ялгана.
- Идэвхтэй Employee-ийн тоо нь өнөөдрийн ээлжид ирсэн хүний тоо биш.
- Хуваарийг менежер оруулна. Бодит ирцийг тусдаа нотолгооноос тооцно.
- AI өөрийн зөвшөөрөгдсөн салбар/ажилтны хүрээний өгөгдөл ашиглана; шалтгаан, KPI босго, цалин/сахилгын шийдвэр зохиохгүй.
- Борлуулалт буурсан ба хоцролт нэмэгдсэн нь дангаараа шалтгаан-үр дагаврыг батлахгүй.
- Өдөр тутмын үйл ажиллагааг бүрэн болгох нь эхний priority; зээлийн модуль хойшлуулсан.

### Бүжигчний одоогийн source-backed contract

- Эхлэх болон хамгийн доод түвшин: **3-р зэрэг**.
- **80-аас доош →3-р зэрэг;80–90-ээс бага →2-р зэрэг;90–100 →1-р зэрэг.**
- Батлагдсан table-service payout mapping:3-р50%,2-р60%,1-р70%. Энэ нь бүх орлого/цалин нэг хувиар тооцогдоно гэсэн дүрэм биш; баримтын огноонд хүчинтэй policy/history-г ашиглана.
- Нийт оноо = finalized өдрийн онооны нийлбэр / тооцогдсон өдрийн тоо. Зөвхөн сонгосон сарын эсвэл зөвхөн өнөөдрийн оноо биш.
- Ирц10%, зочны санал/гомдол15%, борлуулалт40%, бүжгийн ур чадвар5%, цэвэр байдал/төрх5%, өдрийн гараа10%, хувийн хөгжил5%, хандлага10%.
- Баталгаажсан таслалт0оноотой нэг өдөр; батлагдсан бүтэн өдрийн чөлөө болон бүрдээгүй өдөр дундажид орохгүй. Нэг өдөр олон QR бүртгэл нэг өдөр л тооцогдоно.
- Тооцсон шинэ зэрэг/хувь дараагийн өдрөөс хүчинтэй. Ирээдүйн зэргийг өнөөдрийн хүчинтэй зэрэг дээр дарж харуулахгүй.
- Frontend оноо/босго/хувийг дахин бодохгүй; API effective_rank,score,daily_score,counted_days,next_effective_from болон coverage-г хэрэглэнэ.
- Хуучин Gold-оос эхлэх,10,000₮=1rank point,хоёр долоо хоног тутмын rank гэсэн баримтыг энэ contract-ийн оронд хэрэглэхгүй.

### Харуулах мэдээллийн дараалал — одоогийн утгыг баримтжуулсан

**Бүжигчний Нүүр:** хүчинтэй зэрэглэл + нийт дундаж /100; дараагийн зэрэгт дутуу оноо эсвэл батлагдсан өөрчлөлтийн хэрэгжих өдөр. **Дэлгэрэнгүй:** нийт ба өдрийн оноог ялгах; тооцсон өдөр/coverage,8үзүүлэлтийн задаргаа,түүх,шинэчлэгдсэн цаг,policy version. Тухайн салбарын байр эзлэлт нь зэрэглэлийн нэр биш. Бүжигчин зөвхөн өөрийн салбар дахь байр болон нийт хүний тоог харна; бусдын нэр, оноо бүхий leaderboard харуулахгүй. Байрыг backend ижил rank score contract-аар тооцно.

**Харилцагчийн CRM/detail:** серверийн хүчинтэй membership нэр; хамаарах салбар/эрхийн scope; санал болгосон шинэ түвшин ба шийдвэрийн төлөв тусдаа. Онооны үлдэгдэл болон давуу эрхийг тусдаа тайлбарлана. Exact threshold,customer downgrade/anniversary rule,approval authority-г хуучин prototype-оос таахгүй — current policy readback шаардлагатай.

Энэ хэсэг UI-г дахин зурсан эсвэл өөрчилсөн ажил биш; өөр хөгжүүлэгчид нэршил/өгөгдлийн утгыг зөв дамжуулах contract.
